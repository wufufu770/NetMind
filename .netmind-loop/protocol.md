# 无限迭代循环协议

> 本文件是 NetMind 开发流程的**状态机定义**。机器可读的状态真相源是 `.netmind-loop/state.json`。
> 本文件讲「为什么这样设计」；状态文件讲「现在到哪了」。两者冲突以状态文件为准（承 `CONTRIBUTING.md` 的诚实表契约）。

## 为什么需要它

【调研事实】NetMind 的开发轨迹是断裂的：

```
2026-05-18  ██ 2 笔
             ↓ 96 天空窗
2026-08-22  █████ 5 笔
2026-08-23  ████████████ 12 笔   ← 2.5 天内 20 笔
2026-08-24  ██ 2 笔
2026-08-25  █ 1 笔
             ↓ 38 天停滞
```

断裂的根因不是没方向，是**没有「下一步」的稳定定义**。冲刺期靠作者脑内状态驱动，状态一散就停 96 天；恢复时又不知道从哪接。

本协议把「下一步」从脑内状态**外部化到磁盘**：`state.json` 永远持有一份非空待办列表，任何时刻接手都能问出「下一轮做什么」。

## 五个阶段的契约

### BUILD（构建）
- **产出**：一个可验证的增量。**不允许「只改了注释」这种不可验证的增量充数**
- **判据**：改动后 `state.json` 的 `metrics` 至少有���项变化，且该变化能被门禁复现
- **纪律**：`CONTRIBUTING.md` 的「One logical change per commit」——一轮一个 commit 族

### TEST（测试）
- 跑全量单测（`backend/tests/`）
- 跑 `scripts/validate_project.py`（形状门）
- 跑全部门禁

### IMPROVE（改进）
- 门禁失败时**必须**在此阶段产出两件事：**根因**（不是「CI 红了」）+ **修法**（不是「重跑一次」）
- 写进 `state.json` 的 `retro[]`
- **这条是循环不退化的关键**：不记根因的门禁失败会原样复现

### PLAN（规划）
- 从 `backlog` 按 `priority` + `depends_on` 选下一轮
- **`backlog` 为空时自动生成新待办**（见下「永远有下一步」）
- 写进 `state.json` 的 `rounds[]`

### STATE（落盘）
- 每轮结束**必须**写 `state.json`：轮次、指标、待办、retro、round 留档
- 写完才算这一轮结束。**没落盘的轮次等于没跑**

## 门禁与退路

门禁是「带退路」的——每条门禁声明失败时走哪条路，不是简单地「红了就停」。

| 退路 | 行为 | 适用 | 例子 |
|---|---|---|---|
| `block` | 停，等人工决策 | 需要人判断语义的门禁 | 诚实表与实态不一致 |
| `autofix` | 自动执行修复后重跑，最多 `max_attries` 次 | 机械可修的门禁 | 泛化命名清理、生成物 regen |
| `rollback` | `git reset --hard` 回滚本轮，回到上一轮 STATE | 本轮方向错了 | 引入回归 |
| `warn` | 记录进 `retro`，不阻断 | 已知且接受的欠账 | 未做的性能优化 |

**退路优先级的判断**：`block` > `rollback` > `autofix` > `warn`。选 `autofix` 的门槛是**这个修复不涉及判断**——只要需要理解语义才能决定怎么修，就必须 `block`。

## 永远有下一步

【协议硬要求】`backlog` **不允许为空**。空时的处理：

1. 扫描 `metrics` 的趋势线，找**下降或停滞**的指标
2. 扫描 `retro` 里连续出现 ≥2 次的门禁失败 → 提级为待办（技术债固化）
3. 都不命中则从 `state.json` 的 `deferred`（明确推迟项）里捞回最早的一条

**为什么这条是硬要求**：停顿的根因是「没有下一步」。允许 backlog 空 = 允许停顿。协议层面禁止它。

## 状态文件契约

`state.json` 字段：

| 字段 | 含义 | 不变量 |
|---|---|---|
| `cycle` | 已完成轮次 | 单调递增 |
| `phase` | 当前所处阶段 | 只能是 `plan`/`build`/`test`/`improve`/`state` |
| `head` | 对应的 commit SHA | 与实际 git HEAD 一致 |
| `metrics` | 最新指标快照 | 每次落盘刷新 |
| `metric_history` | 指标历史 | 逐轮追加，用于看趋势 |
| `backlog` | 待办 | **非空**（见上） |
| `gates` | 门禁状态 | 与 `gates.py` 声明一致 |
| `rounds` | 轮次留档 | 每轮一条 |
| `retro` | 根因记录 | 门禁失败必填 |
| `deferred` | 明确推迟项 | 供 backlog 空时捞回 |

## 与既有仓库规范的关系

本协议**新增**的只有循环机制。以下全部承自既有规范，不重复定义：

- 诚实表即合同 → `CONTRIBUTING.md` 规则 1
- 禁捏造遥测 → `CONTRIBUTING.md` 规则 2
- 确定性内核、薄适配 → `CONTRIBUTING.md` 规则 3
- 不写注释除非被要求 → `CONTRIBUTING.md` 规则 4
- 营销面可核查律 → `CONTRIBUTING.md` 规则 5（本轮新增）

## 用法

```bash
python3 scripts/loop.py status      # 看当前轮次/阶段/指标/下一轮
python3 scripts/loop.py gates       # 只跑门禁
python3 scripts/loop.py metrics     # 只刷新指标
python3 scripts/loop.py plan        # 规划下一轮
python3 scripts/loop.py commit      # 落盘 state.json
python3 scripts/loop.py round       # 完整跑一轮（test→improve→plan→state）
```
